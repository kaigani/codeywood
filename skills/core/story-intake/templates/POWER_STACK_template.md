### 4. Scene Design Framework

**Every Scene Must Have**:

| Element | Question | Failure Mode |
|---------|----------|--------------|
| **Goal** | What does the POV character want? | Mushy, aimless scene |
| **Obstacle** | What prevents them from getting it? | No tension |
| **Turn** | How does the situation change? | Static, boring scene |
| **Cost** | What did achieving/failing cost? | No stakes |

**Scene Taxonomy**:
- **Dramatic**: Character wants something from another character
- **Procedural**: Character wants information/solution
- **Intimate**: Character wants connection/understanding
- **Action**: Character wants survival/victory

## Framework Variations

### For Procedural-Heavy Shows
- Emphasize Case/Client of the Week structure
- A-story = case, B-story = character/relationship
- Theme reflected in case selection

### For Serialized Drama
- Reduce procedural elements
- Increase relationship axis tracking
- Longer memory for consequences

### For Comedy-Drama (Dramedy)
- Add: Comedy beat requirements per scene
- Modify: Lighter act-outs acceptable
- Track: Joke density by character

### For Ensemble Shows
- Rotate POV by episode
- Track more relationship pairs
- Balance screen time across characters
